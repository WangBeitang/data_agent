## 2026-08-18｜Agent 角色定义优化
决策：角色由单一“决策 Agent”调整为“项目架构师 + 决策 Agent”，统一负责设计文档、架构决策、执行提示词和实现复核。
原则：第一版继续以核心链路上线跑通为优先，非核心边界允许简化或延期。

## 2026-08-18｜归因分析数据对象设计冻结
决策：冻结 RouteResult、AttributionTarget、Action、QueryExecutionResult、Observation、Calculation、Evidence、AttributionState、AttributionReport 九类核心对象；现有 DataAgentState 保持问数 Graph 内部职责，不扩展为归因状态。
原则：Observation 同时保留原始查询结果和归一化结果，Calculator 只消费归一化事实；Planner 不直接生成 SQL；所有归因对象第一版均不持久化。

## 2026-08-18｜统一分析 API 与 SSE 契约冻结
决策：第一版继续使用单一 POST /api/query，通过 mode=auto|query|attribution 控制分析模式；普通问数与经营归因统一使用 SSE，事件通过 JSON type 区分，冻结 route/stage/action_start/query_result/calculation/report/error/done 八类事件。
原则：接口层不暴露完整内部 State；查询事实由 query_result 提供，确定性数值由 calculation 提供，归因结论由 report 提供，所有已建立的流最终以 done 明确 completed/partial/failed 状态。

## 2026-08-18｜模块级 SPEC 前增加只读实施勘察
决策：数据对象与 API 设计冻结后，不提前创建代码框架；先由执行 Agent 对现有代码进行只读实施勘察，再由架构 Agent结合勘察结果生成模块级实施 SPEC。
原则：文件划分、模块职责和依赖方向属于 SPEC 决策范围，避免先实现后补设计；勘察阶段不得修改代码。

## 2026-08-18｜模块级实施 SPEC 冻结
决策：第一版按 7 个 Stage 增量实施；公共分析对象统一放入 `app/models/analysis.py`，现有问数 Graph 仅做结构化结果与稳定 stage_code 的最小改造；Attribution Graph 独立运行并通过请求级 QueryService 复用问数能力。
原则：`analysis_id` 复用现有 `req_id`；归因子查询使用内部 `result_contract` 保证结果可归一化；不新增无必要 Provider 层和基础设施；每个 Stage 完成后停止并复核，普通问数基线必须持续可用。
